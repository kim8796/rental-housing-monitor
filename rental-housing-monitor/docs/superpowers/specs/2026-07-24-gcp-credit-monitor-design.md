# GCP 크레딧 모니터 설계

## 목표

개인 모니터 서비스가 GCP 무료 체험 크레딧 잔액과 프로젝트별 사용액을 매일 수집하고,
텔레그램 자연어 조회·요약·위험 경보를 제공한다. 서버 이전은 준비 상태만 알려주며
사용자 승인 없이 실행하지 않는다.

## 데이터 흐름

1. Cloud Billing Standard usage export를 US 멀티 리전 BigQuery 데이터셋
   `billing_monitor`로 내보낸다.
2. VM 서비스 계정으로 매일 12:10 KST에 고정된 BigQuery 집계 쿼리를 실행한다.
3. 프로모션 크레딧 누적 차감액, 최근 일별 차감액, 이번 달 프로젝트별 비용을
   SQLite 스냅샷에 저장한다.
4. 12:20 KST에 텔레그램으로 잔액·사용률·만료일·예상 소진일·프로젝트별 비용을
   요약한다.
5. “구글 크레딧 얼마나 남았어?” 같은 요청은 같은 최신 스냅샷을 즉시 보여준다.

초기 기준값은 2026-07-24 콘솔 화면의 원금 ₩460,418.00, 잔액 ₩455,463.26,
시작일 2026-07-08, 종료일 2026-10-08이다. 첫 BigQuery 동기화 때 누적 차감액을
기준점으로 고정하고 이후 증분만 콘솔 기준 잔액에서 차감한다.

## 경보와 이전 준비

- 잔액 30%: 주의
- 잔액 10%: 서버 이전 준비 필요
- 잔액 5%: 긴급 이전 경고
- 만료 30일/7일/1일
- 최근 사용 속도로 30일 안에 소진될 것으로 예상될 때

동일 경보는 SQLite 고유 키로 한 번만 발송한다. 10% 이하 메시지에는 최신 암호화
백업 및 검증 시각, 앱 컨테이너·DB 상태, 새 VM에서 다시 연결할 `.env`, Codex 로그인,
IAM/BigQuery/Telegram 체크리스트를 포함한다. 자동 이전은 금지한다.

## 안전성과 이동성

- 금액은 부동소수점 대신 정수 마이크로원으로 저장한다.
- 프로젝트·데이터셋 식별자를 엄격히 검증하고 쿼리 최대 처리량을 제한한다.
- 전체 결제 계정/크레딧 ID, 액세스 토큰, 쿼리 원문은 로그와 텔레그램에 남기지 않는다.
- 메타데이터 서버와 BigQuery API는 코드에 고정된 주소만 호출한다.
- 기준값·스냅샷·경보 이력은 기존 SQLite 암호화 백업에 포함한다.
- 새 VM에는 서비스 계정 권한, `.env`, Codex 로그인만 다시 연결하면 된다.

## 장애 처리

BigQuery export 지연이나 API 오류가 발생하면 마지막 정상 스냅샷을 유지하고 날짜를
명시한다. 반복 실패는 기존 안전 로그와 운영 이벤트로 기록하되 잔액을 추정값으로
덮어쓰지 않는다. 내보내기 테이블이 아직 없을 때도 초기 콘솔 기준값 조회는 가능하다.

## 검증 범위

도메인 계산, SQL/응답 파싱, 저장소 마이그레이션과 중복 경보, 자연어 의도,
12:10/12:20 스케줄, 10% 이전 체크리스트, 설정·Compose·GCP 스크립트를 단위 테스트한다.
전체 테스트와 실제 VM의 데이터셋/IAM/컨테이너/텔레그램 응답을 배포 후 확인한다.
