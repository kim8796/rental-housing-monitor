# URL 없는 모니터 등록 설계

## 목적

사용자가 공개 URL을 몰라도 사이트명·게시판명과 감시 조건만으로 신규 모니터 등록을
시작할 수 있게 한다. 기존 URL 직접 입력 흐름과 최종 등록 승인 절차는 유지한다.

## 흐름

1. URL이 있으면 검색 없이 기존 URL 검증과 등록 미리보기를 실행한다.
2. URL이 없고 사이트 설명이 충분하면 `discovery_query`로 분류한다.
3. 검색 전용 Codex 요청에서만 `web_search="live"`를 사용한다.
4. 공식 운영 주체의 후보 URL을 최대 3개 받고, 각 후보를 URL 정책과 Scrapling 실제
   접속으로 검증한다.
5. 검증 후보가 없으면 추가 설명을 요청한다.
6. 후보가 하나면 기존 등록 미리보기로 바로 연결한다.
7. 후보가 여러 개면 URL을 노출하지 않는 Telegram 선택 버튼을 보여준다.
8. 선택된 URL을 다시 검증한 뒤 기존 등록 미리보기로 연결한다.
9. 사용자가 최종 `등록`을 확인하면 모니터와 사용자별 URL 별칭을 한 트랜잭션에서
   저장한다.

## 신뢰 경계

- 일반 의도 분석, 계획, 복구 요청은 계속 `web_search="disabled"`다.
- 검색 결과와 SQLite 별칭은 모두 불신하며 사용할 때마다 URL 정책과 실제 접속을
  다시 통과해야 한다.
- 검색 실행에서도 command, file change, MCP 도구 이벤트는 허용하지 않는다.
- 후보가 없거나 모호하면 URL을 생성하거나 추측하지 않는다.
- callback에는 URL 대신 소유자에 귀속된 만료형 불투명 token만 노출한다.
- 별칭은 NFKC·대소문자·공백 정규화 후 사용자별로 격리한다.

## 저장 구조

`url_aliases(owner_id, normalized_name, url, updated_at)`를 schema migration 8로
추가한다. 기본 키는 `(owner_id, normalized_name)`이며 사용자가 최종 등록을 승인한
경우에만 upsert한다.

## 비목표

- 일반 대화의 상시 웹 검색
- 검색 API key 또는 별도 검색 과금 도입
- 로그인 자격증명의 자동 수집
- 검증되지 않은 후보의 미리보기·별칭·모니터 저장
