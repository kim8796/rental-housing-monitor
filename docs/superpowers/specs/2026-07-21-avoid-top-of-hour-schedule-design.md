# 정각 예약 누락 회피 설계

## 배경

임대주택 모니터 워크플로는 `0 3 * * *`(한국시간 12:00)에 예약되어 있다. 2026-07-21에는 워크플로가 활성 상태이고 수동 실행도 정상임에도 예약 실행 이벤트가 생성되지 않았다. GitHub는 매시 정각에 예약 실행 부하가 높아 지연되거나 누락될 수 있다고 안내한다.

## 결정

- GitHub Actions cron을 `13 3 * * *`로 변경해 매일 한국시간 12:13에 실행한다.
- README의 실행 시각 설명과 워크플로 회귀 테스트를 같은 값으로 갱신한다.
- 별도 외부 스케줄러나 보조 cron은 추가하지 않는다.
- 배포 후 2026-07-21 누락분을 `workflow_dispatch`로 한 번 실행한다.

## 동작 및 오류 처리

모니터의 수집, SQLite 중복 판별, 텔레그램 전송, 오류 로그 처리에는 손대지 않는다. 수동 실행도 기존 워크플로와 같은 경로를 사용하므로 예약 실행과 동일한 동작을 검증한다. 수동 실행이 실패하면 해당 GitHub Actions 로그를 확인하고 성공으로 보고하지 않는다.

## 검증

1. 기존 워크플로 테스트가 새 예약 시각을 요구하도록 먼저 변경하고 실패를 확인한다.
2. cron과 README를 변경한 뒤 전체 테스트를 실행한다.
3. 변경을 `main`에 푸시한 뒤 수동 실행을 요청하고 완료 상태와 실행 로그를 확인한다.

## 제외 범위

- 정확히 12:00 실행을 보장하는 외부 스케줄러 도입
- 하루 두 번 이상의 백업 실행
- 모니터 애플리케이션 로직 변경
